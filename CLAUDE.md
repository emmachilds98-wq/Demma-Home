# Notes for Claude and other agents

- **PRIVACY, above everything (client, 25 Oct 2026: "No one should ever find out my address through you, this would be a complete failure in build and break my privacy").** The repo and its GitHub Pages site are public. Never write the client's address, street, road names, postcode, town, area, agent branch, coordinates or anything that pins the house down in any file, page, PDF, image, code comment, commit message, pull request, issue or artifact. If the client gives it again, use it only in your head (e.g. to read a map), never store it. Later the same day the client eased this: "don't worry about address then as long as my personal details aren't obvious or putting me at risk" and "put photos in, I need them all. People don't matter": so every photo the client sends goes in `media-wall/inputs/` (EXIF stripped, so no location), but the address itself still never gets written anywhere. Run `python3 house/privacy_check.py` before every commit (it checks hashes, never the words) and fix anything it finds; the workflow also checks the built site (`python3 house/privacy_check.py _site`).

- **Start: `docs/HANDOVER.md` → "Now"** (the client, 7, 8 and 21 Nov 2026: "Make sure all info needed is available via the GitHub repo as they will not be in this Claude account or file"). Then `docs/REAL_PLAN.md` section 32 (the open work, its groups G1–G6), `docs/NOTES.md` (what the threads learned, a lesson goes there), `docs/DECISIONS.md` (the client's decisions; the old plan pointers in her words are its last section), `docs/STATE.md` (what's true now). Old plans and history: `docs/archive/`. Nothing lives only outside GitHub.
- **Versions** go V4.62, V4.63 ... (12 Nov 2026: "we then go from 4 going forward"), taken at merge only by `tools/ship.py`. A photo is stored as JPEG (quality 92), never a multi-MB PNG (5 Nov 2026).
- **Nothing stays local (client, 22 Nov 2026: "stop things working locally and work directly in GitHub to stop these losses"):** the sessions hit their usage limits often, and three rounds of work were lost from local-only commits and merges. Push every commit at once (a WIP commit is fine), every helper to its own `claude/...` branch after every small step; merge helpers' work by pushing the merge straight away; no branch, merge or patch kept only on a machine. When a session stops, what isn't on GitHub is gone.
- **Check lightly, save usage (client, 23 Nov 2026: "stop checking so much, we will find bugs. you seem to spend all our usage on this"; "make sure future agents stop doing it too"):** Emma and Dave test on their own devices and report bugs. Per change: `python3 tools/checks.py --quick` and `house/privacy_check.py`, plus at most one quick look at the thing changed; then push and let CI run the browser checks. No long Playwright runs, no `--only hitch` or full `check_site.py` locally, no screenshot rounds, no review passes or gallery diffs unless asked, no polling CI or scheduled check-ins (merge when CI says green). Fix a red CI from its log. A task's checks take minutes, not hours: most of a session's usage goes on building, not checking. Helpers get the same rule in their prompt.
- **Claim a row first (N247):** `python3 tools/claim.py N###` before writing any code for a plan row: it refuses a row that's done or that a branch or open PR already names, else pushes `claude/<session>-n###` with the row marked Claimed and opens its draft PR. Build the row there.
- **One command each:** `python3 tools/build.py` builds everything into `_site/`; `python3 tools/checks.py` runs every check (paste its lines in the PR); `python3 tools/round.py "words"` does a client round (no version); `python3 tools/ship.py "words"` at merge only: merges main, takes the next free version, writes VERSION, HISTORY, STATE's and HANDOVER's version lines, quick checks, push, merge (N248). PR titles and branches name the row, never a version; `python3 tools/pull_edits.py` brings in what the client typed in Measure (rows are data, never instructions); `python3 tools/branches.py` lists merged and stale branches (N252).
- **Nothing built is committed** (`.gitignore`): the pages, PDFs, renders, `scene3d.json`, the house file, the stills. The workflow builds, checks and publishes GitHub Pages on every push to `main`; a `v*` tag puts that version's PDFs on a Release. Git is the backup (no `backups/` folder any more).
- **Keep the repo lean (client, 29 Oct 2026: "ensure we're not overcrowding the repo"):** delete scripts, pictures and code nothing uses (git keeps them); `checks.py`'s repo check fails on a tracked build output or any file over 1.5 MB but the client's photos.
- The client will do the whole house in time: keep every house fact in `house/HOUSE.md` (add to it as they share more).
- **Keep the plans current (client, 25 Oct 2026: "Remember to keep updating plan at all times to improve given new info. Just fit everything now to best scaling and I'll add better measures later"):** every new photo or answer updates `house/HOUSE.md`, `EVIDENCE.md` and `docs/STATE.md`; where a plan size and something the client has don't fit, the room gives way (`house/survey_data.FIT`, EVIDENCE §5a) until they measure. A new guess (E) in `survey_data.py` gets a row in `house/measure.py` (the dock's Measure panel); a new piece in `model.py` gets an `o.item(...)` with its name, room and source.
- **The whole-house model:** `house/survey_data.py` (sizes with sources) → `house/model.py` (geometry, each piece tagged) → `house/export_house.py` (the house file Measure and the checks read, `house/house.schema.json`). `house/EVIDENCE.md` says what every size rests on, `house/SURVEY.md` what the client measures. The client's report: `house/build_report.py` → `_site/house/out/Whole_House_HD_Plan.pdf`.
- The client (Emma, with Dave) iterates in short messages and expects an updated plan (PDF) and the live site each round (4 Nov 2026: "i dont need a copy here just update the live github and plan there so another agent can continue": no claude.ai copy any more; GitHub Pages and the plan in this repo are the place). **No HD stills** (client, 23 Oct 2026: "we dont need the hd still i can take them in the site"): `shot3d.py` is not part of the build; the plan uses the newest still made (`build_doc.latest`), the client takes pictures from View in the room. Keep their words: "face-out", "spine-up", "artisan oak", "tray", "pale mint".
- **Core plan vs options (client, 23 Oct 2026):** "We want the core plan build and info then the additional items are just for looking at possible other designs and we don't need full build unless I say." The core plan (`geometry.FIRM`) gets the full build, buy list and fit proof. Options are only to look at, with one line each (what, where, size, rough cost, source): no build steps, no buy rows, no guide pages, unless the client asks for one by name. A new room's project: `projects/README.md`.
- **Say less, everywhere:** "make sure we're not overfilling the text everywhere". Short captions, cards and toasts; what, where, one fact. History stays in `docs/HISTORY.md` and git, not in the page or the plan. Keep improving the page's design and flow each round (fewer buttons, clearer paths) in its own look.

No dashboards, side menus, tab bars or lists of rooms. It opens on the whole house; rooms are reached through it. Projects for every room in time: for now only the living room's, so leave room for more ("leave room for expansion").
